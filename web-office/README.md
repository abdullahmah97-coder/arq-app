# مكتب أرك أب على الويب

صفحة تنفتح داخل claude.ai (Artifact) وتدير منها التطبيق كله من الكمبيوتر: نظام تشغيل الشركة (مبنى ثلاثي الأبعاد لكل الفرق)، وحالة المهام،
وموافقة أو رفض مقترحات الوكلاء وطلبات الشركاء، وتشغيل الوكلاء، ولوحات أرقام كل الأقسام.

- الصفحة ما تكلّم قاعدة البيانات مباشرة (claude.ai يمنع الاتصال المباشر). كل قراءة وكل إجراء يمر من **موصّل Supabase**
  في claude.ai (أداة `execute_sql`) بحساب المالك نفسه — الدوال اللي تستدعيها: `office_overview` و `office_admin.*`
  (الشرح الكامل في `docs/office-web.md`).
- لو انفتحت الصفحة بدون الموصّل تعرض بيانات تجريبية (`sample.json`) مع شريط واضح.
- مع مشكلة اتصال ما نقدّم التجريبي كأنه بياناتك أبد: لو ما وصلت بيانات حية للحين تبقى التجريبية والشريط يقول صريح إنها تجريبية
  (ومع «Supabase ما ردّ» الصفحة تعيد المحاولة لحالها مرة كل دقيقة)؛ ولو فيه بيانات حية تبقى ظاهرة كآخر بيانات وصلت والإجراءات توقف
  لين يرجع الاتصال. لو الحساب تغيّر نمسح البيانات ونوقف كل الاتصالات.

## تبويب «المكتب»: نظام تشغيل الشركة
أعلى التبويب واجهة على شكل بوستر «AI Company OS»: عنوان كبير، بطاقات، ومبنى مقطوع ثلاثي الأبعاد كل دور فيه فريق وكل غرفة مكتب.
- **٧ شرائح** (شريط فوق فيه زر لكل فريق مع شارة «ينتظرك»، وسابق/تالي، و«n/7»؛ الشريحة تنحفظ بالمتصفح `arqOffice.slide`):
  | الشريحة | المبنى | البطاقات |
  |---|---|---|
  | المقر `hq` | ٦ أدوار = ٦ فرق (المدير، الشركاء، العمليات، المجتمع، النمو، المهندسين)، ١٣ غرفة | ٦ فرق ← تفتح شريحة الفريق |
  | المدير `ceo` | غرفة المدير التنفيذي (مكتب، صالة، شاشة كبيرة، لوحة «الرؤية») | قرارات تنتظرك، فرق تشتغل، أقدم انتظار، ملخص اليوم (يشغّل وكيل المدير) |
  | الشركاء `partners` | الأندية، المتاجر، المدربين، المراكز | بطاقة لكل مكتب ← تختاره |
  | العمليات `ops` | النشاط، الحجوزات، الطلبات | بطاقة لكل مكتب |
  | المجتمع `community` | المجتمع، التقارير | بطاقة لكل مكتب |
  | النمو `growth` | التسويق، الذكاء الاصطناعي | بطاقة لكل مكتب |
  | المهندسين `eng` | غرفة المهندسين (خط البناء، شاشات الكود، الخادم) | طلب تعديل (نموذج تبويب «التطبيق») + يبنون / مراجعة / انتهى (قائمة الطلبات) |
- الأسهم ←/→ تتنقّل وأنت داخل الواجهة (بالعربي «التالي» يسار)، وما تاخذ الأسهم من الحقول. ضغطة غرفة بالمقر تفتح شريحة فريقها
  وتختار المكتب؛ بشريحة الفريق تختار المكتب ولوحته تحت (بالجوال تنزل لها). «افتح المكتب» من اللوحات أو أي مكان ثاني ينقلك لشريحة فريقه،
  والتنقّل لشريحة فريق ثاني يختار أول مكتب فيه (لوحة المكتب تحت تتبع الشريحة).
- **المبنى** (`createCompanyOS` في `src/4-scene.js`، three.js r158 الأساسي): الشاشات تعرض أرقام المكتب الحية (`deskMetrics`، رسم يومي،
  قائمة المهام المفتوحة أو قائمة المكتب)، والشاشات الصغيرة تتلوّن بالحالة (برتقالي ينتظرك، كهرماني يشتغل، أخضر هادي) واللي ينتظرك
  يرفع يده. فوق كل غرفة زر شفاف (للتركيز والقارئ: الاسم + ينتظرك/شغّال/تحتاج نظرة) مع شارة العدد على خط البلاطة فوقها
  (برتقالي ينتظرك، كهرماني يشتغل، أزرق تحتاج نظرة). غرفة المهندسين أرقامها من طلبات التعديل
  (`office_admin.requests`: تتحمّل لما تفتح شريحتهم بالحي — وزر «تحديث» يعيد تحميلها — وبالمعاينة من `sample.json`).
- عرض المبنى يتبع شكل المسرح (بالشاشات العريضة أعرض ويتعبّى بمكاتب أكثر)، وارتفاع المسرح من مكانه بالصفحة (`--os-top`)
  عشان «خط سير العمل» يبان بأول شاشة حتى مع شريط البيانات التجريبية.
- **الخطوط البرتقالية** من كل بطاقة لحافة دورها بالمبنى (جهة النص)، بالشاشات ١٠٠٠px وفوق بس؛ تحتها الواجهة فوق بعض بدون خطوط.
  البطاقات تنزل لمستوى أدوارها لو فيه مكان (الخطوط شبه أفقية)، والكوع الصغير ينعدل خط مستقيم.
  المبنى يلصق بجهة النص بالشاشات العريضة (`setAlign`) و«خط سير العمل» يجي تحته بالضبط.
- **خط سير العمل** لكل شريحة (مثلاً الشركاء: طلب جديد ← الوكيل يراجع ← موافقتك ← ينضم) مع أرقام حية لكل خطوة،
  وتحته «اليوم للحين» ثم لوحة المكتب المختار و«حالة المهام» واللوحات.
- بدون WebGL (أو زر 2D): **مبنى مسطّح** من نفس الخطة (سقف بلافتة، أدوار، غرف غامقة بأرقامها وشاراتها) — نفس الضغطات.
  المدير والمهندسين (غرفة وحدة): غرفة طويلة فيها كل الأرقام وخط البناء والقائمة. ولو three.js تأخّر أكثر من ١٫٢ ثانية
  يطلع المسطّح وهو يتحمّل ويتبدّل للـ 3D لما يجهز؛ ولو WebGL انفقد مؤقتاً يرجع لحاله لما يرجّعه المتصفح.
- الحالة فوق: «كل الأنظمة تعمل» بس لو مباشر وأرقام المكتب والمهام انحمّلت وما فيه أعطال اليوم؛ «يعمل · أعطال اليوم: N»،
  و«يعمل · بعض البيانات ما انحمّلت» لو قسم فشل.
- الألوان كلها رموز تشتغل بالفاتح والداكن؛ الخطوط: Anton (العنوان الإنجليزي)، IBM Plex Mono (العناوين الصغيرة والأرقام)،
  Noto Kufi Arabic (العربي). مع «تقليل الحركة» المشهد يرسم إطار ثابت والتبديل بدون تلاشي (ويرسم إطار جديد لما توصل الخطوط
  متأخرة — المشهد يعيد رسم الشاشات مع `loadingdone`).

## تبويب «التطبيق»
الشريط العلوي فيه تبويبين: «المكتب» (نظام الشركة واللوحات) و«التطبيق»:
- **طلبات التعديل**: تكتب وش تبي يتغيّر في التطبيق (عنوان، قسم، تفاصيل) ← تأكيد داخل الصفحة ← الصفحة تفتح جلسة Claude Code
  (موصّل **Claude Code Remote**: `create_session` على مستودع التطبيق، فرع جديد وطلب دمج للمراجعة — ولا شي يوصل للمستخدمين لين تدمجه
  بنفسك) وتحفظ الطلب بـ `office_admin.add_request`. القائمة (`office_admin.requests`) تتابع حالة كل جلسة مفتوحة (`get_session`
  لما ينفتح التبويب وكل دقيقة، ١٠ بالكثير) وتحفظ التغيّر ورابط طلب الدمج بـ `update_request`. «أرسل ملاحظة» = `send_message`،
  و«إلغاء» يعلّم الطلب بس (ما يوقف الجلسة). لو الجلسة انفتحت والحفظ فشل، رابطها يبقى ظاهر مع «أعد الحفظ»
  (وينحفظ بالمتصفح لين ينحفظ الطلب، والإغلاق يحتاج تأكيد ويمسح النموذج). لو `create_session` ما ردّ (طوّل أو انقطع) الصفحة ما تقول
  «ما انفتحت»: تقول إن الجلسة يمكن انفتحت وتطلب تشيّك claude.ai/code قبل أي إرسال ثاني (والإرسال الثاني بتأكيد «جلسة ثانية»).
  الإرسال يوقف لو القاعدة ما تقدر تحفظ الطلبات (الدوال ناقصة، صلاحيات، للقراءة بس). فحص الحالات ما يكتب فوق طلب ألغيته وهو شغّال،
  ورابط طلب الدمج ينقرا من رد الجلسة بس (مو من عنوانك أو تفاصيلك)، والأكبر رقم يفوز.
  بدون الموصّل: الصفحة تقول كيف تضيفه (claude.ai ← الإعدادات ← الموصّلات) والطلبات المحفوظة تبقى ظاهرة.
- **المحتوى والإعدادات** (كله `office_admin.*`): إعلان البداية (تعديل وتشغيل/إيقاف — الإعلان الجديد بصورته من الجوال)، الفعاليات
  (إضافة وتعديل وإظهار/إخفاء)، تنبيهات التحفيز (فلترة، تعديل، جديد موقوف، تفعيل/إيقاف)، الإعدادات (حدود الذكاء الاصطناعي وتنبيه
  السعرات)، الشركاء (إخفاء/إظهار/شريك)، المتدربين (بحث وصفحات بدون إيميلات، تعديل الاسم واسم المستخدم، التوثيق ✓).
  كل حفظ يوريك وش بيتغيّر (القديم ← الجديد) ويطلب تأكيد، ويرسل المفاتيح اللي تغيّرت بس.
- الصلاحيات اللي تنشر معها الصفحة:
  `{ mcp: { servers: [ { server: "Supabase", tools: ["execute_sql"] }, { server: "Claude Code Remote", tools: ["create_session", "get_session", "send_message"] } ] } }`

## التعديل والنشر
- الكود في `src/` (الأنماط `style.css` ثم واجهة نظام الشركة `style-os.css`، العناصر، الترجمة `1-i18n.js` + `1b-i18n-app.js`، الأساس
  (الشرائح `OS_SLIDES`)، الواجهة (`renderHero` وخطة المبنى `buildPlan`)، المشهد `4-scene.js` (`createCompanyOS`)، تبويب التطبيق `5-app.js`،
  التشغيل `6-main.js`).
- `node web-office/gen_sample.cjs` يولّد `sample.json` بنفس شكل `overview.sample.json` (نتيجة حقيقية من اختبار القاعدة)،
  ومعه بيانات تجريبية لتبويب التطبيق (`app`: طلبات، إعلانات، فعاليات، تنبيهات، إعدادات، شركاء، متدربين — بنفس مفاتيح docs/office-web.md القسم ٧).
- `node web-office/build.cjs` يجمّعها في `web-office/index.html` (ملف واحد، ينتشر كما هو).
- `node web-office/check.cjs` يتأكد من قواعد صفحات claude.ai (العنوان أول شي، بدون html/head/body، سكربتات من CDN مسموح بس، بدون alert/innerHTML)،
  ومن البيانات التجريبية، ومن إن كل نص له عربي وإنجليزي بنفس المتغيرات.
- النشر من جلسة Claude: نفس رابط الـ Artifact، مع صلاحية `mcp` لموصّل Supabase (`execute_sql`) وموصّل Claude Code Remote
  (`create_session`, `get_session`, `send_message`) — الشكل فوق.
